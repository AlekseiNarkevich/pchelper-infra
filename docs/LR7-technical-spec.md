# Техническое задание ЛР7 — витрина каталога PCHelper

**Проект:** PCHelper — интернет-магазин компьютерных комплектующих и готовых ПК
**Команда:** StudentsTrio — Наркевич А. С. (тимлид), Бирюк И. А., Бельский Т. Д.
**Основание:** методические указания к ЛР7, этап 1 — «Техническое задание».
**Срок:** 11.11.2026.

## 1. Цель этапа

Начать реализацию проекта: поднять серверную часть с реальными сущностями
и API, подключить её к действующей базе Supabase, собрать первые экраны
веб-приложения и проверить весь путь через CI/CD с публикацией на Render.

Лабораторная — последняя в курсе; после неё проект продолжается как
курсовая работа 4 курса. Поэтому код и структура репозитория сразу
проектируются как основа магазина, а не как одноразовая демонстрация.

## 2. Что входит в этап

| № | Работа | Результат |
|---|---|---|
| 1 | Сущность «Товар»: восемь категорий комплектующих из Supabase | единый объект `Product` для всех категорий |
| 2 | API каталога: категории, список с фильтрами, карточка товара | 4 маршрута под `/api/v1` |
| 3 | Готовые сборки: состав и цена из связанных таблиц | `GET /api/v1/prebuilt` |
| 4 | Веб-витрина: главная, каталог, карточка товара | React + Vite, три страницы |
| 5 | Автотесты API | `node:test`, не менее 20 проверок |
| 6 | CI/CD: линт, тесты, качество кода, сборка образов, деплой | GitHub Actions |
| 7 | Публикация | Render, рабочая ссылка |

## 3. Что сознательно не входит

Авторизация, корзина с сохранением на сервере, оформление заказа, отзывы,
платежи, доставка, админка. Эти функции проектировались в ЛР1–ЛР3 и входят
в курсовую 4 курса; в ЛР7 они не реализуются, чтобы не распылять три дня
до сдачи. Кнопка «В корзину» на витрине сохраняет выбор в localStorage —
это демонстрация сценария, а не серверная корзина.

## 4. Источники данных

**Supabase** — основная база. Десять таблиц с кириллическими именами:

| Таблица | Строк | Что хранит |
|---|---|---|
| `Процессоры` | 16 | сокет, ядра/потоки, частота, TDP, память |
| `МатеринскиеПлаты` | 17 | сокет, чипсет, тип памяти, форм-фактор |
| `ОЗУ` | 12 | тип, объём, частота, тайминги |
| `Видеокарты` | 9 | память, длина, TDP, вентиляторы |
| `БлокиПитания` | 10 | мощность, сертификаты, разъёмы |
| `Накопители` | 17 | объём, интерфейс, скорость, DRAM |
| `Корпуса` | 7 | форм-фактор, ограничения по длине |
| `СистемыОхлаждения` | 8 | тип, TDP, высота, шум |
| `ГотовыеКонфигурации` | 7 | ссылки на восемь комплектующих |
| `КонфигурацияНакопители` | 12 | связь сборки и накопителей |

У всех таблиц каталога есть `название`, `цена` (в BYN) и `фото_url`
(публичная ссылка Supabase Storage).

**Фикстура** — снимок двух товаров на категорию и трёх сборок. Используется
только в CI и при запуске без ключей. Форма объектов та же, что у Supabase,
поэтому подмена источника не меняет контракт API.

## 5. Контракт API

Базовый префикс — `/api/v1`. Ошибки — в формате
`{ "error": { "code": "...", "message": "..." } }`.

### GET /categories

Список восьми категорий с количеством товаров.

### GET /products

Параметры: `category`, `search`, `minPrice`, `maxPrice`,
`sort` (`price_asc` | `price_desc` | `name_asc`), `limit` (1–100), `offset`.

Ответ: `{ items, total, limit, offset }`.

### GET /products/:id

Идентификатор составной: `cpu:12`, `gpu:3`. Ответ — объект товара:
`id`, `category`, `categoryName`, `name`, `price`, `currency`,
`imageUrl`, `description`, `specs[]`.

### GET /prebuilt

Готовые сборки: `id`, `name`, `task`, `price`, `currency`, `imageUrl`,
`components[]`, `componentCount`. Цена считается как сумма цен деталей:
отдельного поля цены в таблице сборок нет.

## 6. Нефункциональные требования

* Node.js 22+, ES-модули, Express.
* Ответ API — не более 300 мс на локальной базе (10–17 строк в таблице).
* Покрытие тестами — не менее 70 % строк backend.
* Сборка Docker-образа и деплой — только после зелёных тестов и
  положительной проверки качества кода.
* Секреты (ключи Supabase, токены) — только в переменных окружения,
  в репозиторий не попадают.

## 8. Критерии приёмки

1. `GET /api/v1/categories` возвращает 8 категорий с реальными количествами.
2. `GET /api/v1/products` отдаёт 96 товаров из Supabase и поддерживает
   фильтр, поиск, сортировку и страницы.
3. `GET /api/v1/products/cpu:1` возвращает карточку с характеристиками.
4. `GET /api/v1/prebuilt` возвращает 7 сборок с ценой из деталей.
5. Витрина открывается, показывает категории, товары и карточку товара.
6. Конвейер GitHub Actions зелёный, образы собраны, Render отвечает.
7. Отчёт содержит распределение работ и ссылки на коммиты.
