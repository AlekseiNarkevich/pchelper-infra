## Что где лежит

Диаграмма выше показывает **целевой вид проекта** — интернет-магазин
из четырёх репозиториев. Этот репозиторий — учебный стенд
лабораторной работы № 4: здесь лежат те части, которые удалось
собрать и проверить целиком. Ниже — что именно в нём находится.

| Каталог | Назначение | Ключевые файлы |
|---------|-----------|----------------|
| `backend/` | Серверное приложение: Node.js 20 + Express. Приложение «Hello World» и проверка готовности окружения — пункт 9 задания 6 | `src/server.js` — точка входа и healthcheck; `src/app.js` — маршруты и обработка ошибок; `src/routes/hello.js`, `admin.js`; `tests/` — 9 автоматических тестов; `Dockerfile` |
| `frontend/` | Веб-контейнер: nginx со страницей проверки, что окружение поднялось и backend отвечает | `public/index.html`, `nginx.conf`, `Dockerfile` |
| `mcp/` | MCP-сервер задания 5: Python 3.12 и MCP Python SDK. Читает ту же схему данных, что и backend | `server.py` — регистрация примитивов; `services.py` — вся бизнес-логика; `audit.py` — журнал действий агента и маскирование PII; `db.py`, `healthcheck.py`; `schema.sql`, `seed.sql`; `tests/` — 39 тестов; `README.md`; `requirements.lock` |
| `db/` | Физическая модель базы данных — задание 2. 23 таблицы, 72 индекса, 4 триггера | `01_schema.sql` … `05_seed.sql`, `06_check.sql` — 14 проверок модели |
| `api/` | Спецификация API — задания 3 и 4. Единственный источник правды: из неё собирается и бэкенд, и документация | `openapi.yaml` — 39 операций OpenAPI 3.0.3 |
| `diagrams/` | Исходники диаграмм PlantUML и готовые PNG | `plantuml/*.puml` — 14 диаграмм |
| `docs/` | Сайт документации — этот сайт. Публикуется на GitHub Pages из папки `docs` ветки `main` | 10 страниц, `style.css`, `img/` — 14 PNG |
| `wiki/` | Исходники страниц вики. Заливаются в `pchelper-infra.wiki.git` | 9 страниц по требованиям методички |
| `.github/` | Непрерывная интеграция | `workflows/ci.yml` — конвейер из шести этапов |
| `sonar-project.properties` | Настройка проверки качества кода для SonarQube и SonarCloud | область анализа, пути OpenAPI, ожидание Quality Gate |
| `docker-compose.yml` | Локальное окружение из пяти контейнеров одной командой `docker compose up -d --build` | postgres, redis, api, web, mcp |

## Как связаны части

| Связь | Что происходит |
|-------|----------------|
| `backend` → `db/` | Репозитории обращаются к готовым DDL-скриптам. Схема базы описана один раз и не может разойтись с кодом |
| `mcp` → `db/` | Сервер MCP читает ту же схему, что и бэкенд: имена таблиц совпадают, расхождение исключено |
| `frontend` → `backend` | nginx отдаёт статику и проксирует запросы `/api` на контейнер бэкенда по внутренней сети Docker Compose |
| `api/openapi.yaml` → всё | Спецификация API проверяется линтером, из неё собирается статическая документация. Код и документация не расходятся |
| `.github/workflows/ci.yml` → всё | Конвейер проверяет код, анализирует качество, собирает образы и разворачивает сервис — но только после зелёного Quality Gate |

> Часть модулей из диаграммы (React-клиент, модули `controllers`
> и `services`, нативное Android-приложение) появится при переносе
> стенда в курсовую работу. Здесь они намеренно не показаны: в
> лабораторной работе они не реализованы, и выдавать план за
> сделанное не нужно.
